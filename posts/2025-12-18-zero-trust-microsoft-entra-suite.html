Unlocking Zero Trust: Mastering Identity and Network Security with Microsoft Entra Suite

A deep dive into the Microsoft Entra Suite and how it enables a Zero Trust security model for modern organizations.

The Microsoft Entra Suite brings Zero Trust Network Access (ZTNA) from whiteboard concept to operational reality. Traditional perimeter defenses cannot keep up with modern threats because they treat the network boundary as the trust boundary — and that boundary no longer exists. Entra Suite replaces it with identity-centric verification: every user, every device, every session gets evaluated against real-time risk signals before access is granted. This article walks through the components, the deployment phases, and the practical decisions that determine whether a Zero Trust rollout succeeds or stalls. If you are new to the model, start with the Zero Trust in Microsoft 365 guide.

Why a Unified Identity and Network Security Strategy Is Critical

A unified approach ties identity verification and network access together, treating every access request as an opportunity to reassess trust based on real-time signals. Microsoft Entra Suite is designed exactly for this: an integrated platform combining identity and access management with secure network access controls to enable Zero Trust across the board.

What Is Microsoft Entra Suite? Key Features and Benefits

Microsoft Entra Suite is a bundle of five services: Microsoft Entra ID Protection, Microsoft Entra ID Governance, Microsoft Entra Verified ID, Microsoft Entra Internet Access and Microsoft Entra Private Access. Be precise about two things people routinely put in that list: Conditional Access is an Entra ID P1 feature that the Suite builds on (the Suite does include all Conditional Access features), and Privileged Identity Management comes in through the ID Governance component — neither is a standalone Suite product. Licensing sits on top of Entra ID P1, which the Suite requires; for how the underlying tiers compare, see the Entra ID pricing guide (P1/P2).

Zero Trust Network Access (ZTNA) with Global Secure Access

Entra Suite delivers Zero Trust Network Access through Global Secure Access, and it works through three traffic forwarding profiles, not two. Traffic is evaluated against them in this order:

  • Microsoft traffic — Exchange Online, SharePoint and OneDrive, Teams and other Microsoft apps. This one needs only Entra ID P1 or P2, no Suite, which is why it is usually the first profile a tenant turns on.
  • Private access — your internal applications. Requires Entra ID P1/P2 plus Microsoft Entra Private Access or the Entra Suite, and configured Quick Access with the FQDNs and IP addresses of the private apps. Runs over the Global Secure Access desktop client.
  • Internet access — SaaS and the open web. Requires Entra ID P1/P2 plus Microsoft Entra Internet Access or the Entra Suite.

Traffic that matches none of the three is not forwarded at all. And note what the Internet access profile does not cover: it explicitly excludes the destinations handled by the Microsoft traffic profile. Microsoft's own guidance is to enable the Microsoft traffic profile together with the Internet access profile for complete coverage — turn on Internet Access alone and your Microsoft 365 traffic stays unmanaged.

The other thing worth knowing before you buy: Private Access and Internet Access are available standalone. The full Suite is not the only route in.

Instead of dropping a remote user onto the whole network the way a broad VPN does, Global Secure Access grants access to one specific application at a time and runs every connection through Conditional Access. This is the difference between Zero Trust vs perimeter security: trust is evaluated per request, not assumed once you are "inside."

The Lockout Trap Nobody Warns You About

This is the documented failure mode that can end a rollout, so plan for it before you enable anything. Both the Microsoft traffic and Internet access profiles authorize their tunnels through Conditional Access. That means a Conditional Access policy can block a profile — and if the recovery path runs through a destination on that same blocked profile, the user is locked out of everything on the machine.

The textbook example: you block the Internet access target resource on non-compliant devices. Now a user whose device drifts out of compliance cannot reach the endpoints needed to bring it back into compliance. Dead end.

The mitigation is to add a custom bypass in the Internet access forwarding profile for the Microsoft Intune network endpoints, plus any destinations your custom compliance discovery scripts reach. Microsoft publishes a PowerShell sample that adds the Intune endpoints to that bypass policy — use it rather than typing the list by hand.

In the Private Access rollouts I have worked on, the hardest part is rarely the technology — it is mapping which applications each role actually needs, so access stays least-privilege instead of quietly drifting back toward "everyone can reach everything." That discovery work is where a ZTNA project succeeds or stalls, and it is not optional: Quick Access wants the FQDNs and IP addresses of every private app you intend to publish. You cannot skip the inventory; the product asks for it.

The Microsoft Zero Trust Workshop

First, the name: it is the Microsoft Zero Trust Workshop, not an Entra Suite workshop. It is not Entra-specific at all — it covers seven pillars: Identity, Devices, Data, Networking, Infrastructure, SecOps and AI.

Second, it is no longer a spreadsheet. If you remember it that way, that version is gone. It now has three components:

  • An assessment tool — a PowerShell module you run in your own tenant. It collects configuration data, checks it against a broad set of Zero Trust best practices, and produces scores, gaps and recommendations per Zero Trust pillar and per Microsoft Secure Future Initiative pillar. This is the part that makes the output real rather than aspirational.
  • A Workshop tool — a single-page app for documenting progress and building the roadmap.
  • Workshop guidance — written articles per pillar, for facilitators and participants.

The structure is four phases, repeated per pillar: Phase 1 Kickoff/Orientation, Phase 2 Assessment (optional), Phase 3 Roadmap, Phase 4 Closeout. You can run it as a Microsoft- or partner-led engagement, or self-service with the guidance and the assessment tool.

One caveat to mention if you are recommending it to a customer: Microsoft maintains the Workshop on GitHub as a community-style resource, provided "as-is" with best effort, and it is not covered by Microsoft support. That does not make it less useful — it makes it something you own once you start it.

Key Takeaways & Best Practices

Three things decide whether this lands:

  • Run the assessment before the roadmap. Phase 2 is technically optional. Skip it and Phase 3 becomes a wish list instead of a plan, because you are prioritising gaps you have not measured.
  • Get the right people in the room, by name. Microsoft is specific about who: the security strategy owner (CISO, security architects), a pillar owner per pillar, decision makers and budget stakeholders (CTO, CIO, business app owners), risk program owners, and the cross-functional staff who actually operate the systems. A workshop without a budget holder produces a roadmap nobody funds.
  • Start with the Microsoft traffic profile. It needs only P1, it covers the traffic your users generate all day, and it lets you learn the operational model before you put your internal apps behind it.

Final Thoughts: Take the Next Step Toward Zero Trust Mastery

The Microsoft Zero Trust Workshop gives you two things a strategy document cannot: measured baseline data from your own tenant, and a roadmap built on that data rather than on assumptions. That is what turns a fragmented set of security projects into a sequence you can actually work through.

Frequently Asked Questions

What is ZTNA in Microsoft Entra?

Zero Trust Network Access (ZTNA) in Microsoft Entra is delivered through Global Secure Access, which uses three traffic forwarding profiles: Microsoft traffic (Exchange Online, SharePoint, OneDrive, Teams — needs only Entra ID P1), Private access (internal apps — needs Entra Private Access or the Entra Suite), and Internet access (SaaS and the open web — needs Entra Internet Access or the Entra Suite). Instead of granting broad network access like a VPN, it verifies identity, device, and context on every connection and grants access only to the specific app.

Does Microsoft Entra replace VPN?

For many scenarios, yes. Entra Private Access (part of Global Secure Access) provides per-application access to internal resources without exposing the whole network, replacing traditional VPN for most remote-access needs. It applies Conditional Access and continuous verification a classic VPN can't. Some legacy or non-web protocols still need careful planning.

What's included in the Microsoft Entra Suite?

The Entra Suite bundles Entra ID Governance, Entra Private Access, Entra Internet Access (together Global Secure Access), Entra ID Protection, and Entra Verified ID — unifying identity and network security under one Zero Trust platform.
